# 스킬 승격과 다이어트

스킬은 공짜가 아니다. **description은 매 프롬프트마다 읽힌다.** 만들기만 하면 6개월 뒤 스킬 자체가 낭비 원인이 된다.

공개 skill 55,315개 분석에서 26.4%는 라우팅 설명이 아예 없었고, body의 60% 이상이 실행에 쓰이지 않는 내용이었다(SkillReducer). 설명 48%·본문 39%를 줄였을 때 기능 품질은 오히려 2.8% 올랐다.

## 절차

1. 후보를 본다.

   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/scripts/ai_saver_cli.py" promote --list
   ```

   `ai_saver/promotion.py`의 `PURPOSE` 표에 있는 코드만 후보가 될 수 있다. 매번 새 이름을
   지어내지 않는다 — 이미 정의된 명령(`focus-file`, `scoped-edit`, `quick-test`, `ui-edit`,
   `project-brief`, `wider-edit`) 중 하나로 귀결된다. 표에 없는 낭비 패턴이 새로 보이면,
   승격하기 전에 `ai_saver/promotion.py`의 `PURPOSE`에 항목을 추가하는 것부터 한다.

2. 아래 5개를 확인한다. **하나라도 실패하면 만들지 않는다.**

   | # | 조건 | 확인 방법 |
   |---|---|---|
   | 1 | 30일 내 5회 이상 | `promote --list`가 보여주는 횟수 (미달이면 CLI가 자체적으로 거부한다) |
   | 2 | 원인 신호가 같다 | 같은 명령으로 묶인 코드들인지 `--list` 출력에서 확인 |
   | 3 | 예상 절감 > 상시 비용 × 30일 | 상시 비용 = description 토큰 × 하루 프롬프트 수 × 30. 이 계산을 사용자에게 한 줄로 보여주고 판단을 구한다 — CLI는 이 판단을 하지 않는다 |
   | 4 | description ≤ 500자, 본문 ≤ 60줄 | `promote` 실행 시 자동으로 강제된다 (넘으면 에러) |
   | 5 | 상세 내용은 본문이 아니라 참조로 | 템플릿이 이미 규칙만 담게 되어 있다 |

3. 조건 3(판단)까지 통과했으면 실제로 만든다.

   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/scripts/ai_saver_cli.py" promote <명령 이름>
   ```

   `~/.claude/skills/<이름>/SKILL.md`가 만들어지고, **그 순간 `/`에 뜬다.** 사용자에게
   "`/이름`을 쳐서 자동완성에 뜨는지 확인해보세요"라고 알려준다.

## 스킬 예산

개인 스킬 description 합계 **2,000 토큰 이하**. 넘으면 새로 만들지 말고 **기존 스킬에 합친다.**
`promotion.py`의 `render_skill`은 같은 명령으로 묶인 코드들을 이미 자동으로 병합한다.

## 감가상각

- 30일 0회 호출 → 리포트에 삭제 후보로 표시
- 90일 0회 호출 → 삭제 제안, 승인되면 `~/.claude/skills/<이름>/` 폴더를 지운다

## 작성 규칙

- 본문은 **행동 규칙만.** 배경 설명·정당화·예시 나열은 뺀다.
- 규칙은 금지형보다 범위형으로: "전체를 보지 마라"(X) → "지목한 파일과 그 style 파일만 읽는다"(O)
- `text-optimizer` skill이 있으면 생성 직후 통과시킨다.

## 승격 후 확인

다음 달 리포트에서 해당 습관 횟수가 줄었는지 본다. **안 줄었으면 스킬이 틀린 것이다.** `~/.claude/skills/<이름>/` 폴더를 지우거나 `PURPOSE`의 규칙을 고쳐 다시 `promote`한다.
